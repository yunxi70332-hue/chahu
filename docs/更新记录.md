## v2.7 管理员提现审核（2026-09-18）

### 变更背景

此前提现只有「线下转账后管理员在用户管理记账」一种模式，代理/会员无自助入口，总部无法留痕核对收款信息。v2.7 新增「申请 → 审核」流，与手工记账**两通道并存**（用户管理余额调整行为不变）。

### 新增功能

1. **我的提现页**（AGENT/MEMBER）：当前余额 + 可用余额（= 余额 − 待审中合计）双卡展示；「申请提现」弹窗（金额 / 收款方式三选一 / 收款账号 / 收款人姓名默认带出实名姓名）；申请记录表（状态、驳回原因、通过后关联流水号与打款时间），待审单可**撤销**；未实名者显示引导横幅跳实名认证。
2. **提现审核页**（ADMIN）：筛选（状态/日期/提现单号）+ 待审合计条；审核弹窗展示申请人、联系方式、收款信息，**通过打款**走二次确认（扣余额 + 写 WITHDRAW 流水），**驳回**两段式展开原因框（必填，不动余额）；已审核单只读回看。
3. **看板新卡**（仅 ADMIN）：「提现待审」警示卡，点击直达 `/withdraw-review?status=PENDING`。
4. **业务规则**：申请须已实名通过；可用余额防超额申请；审核通过时余额不足则 400 引导驳回；事务内复查状态防并发双审双扣。

### 接口变更

| 接口 | 变更 |
| --- | --- |
| `POST /api/withdraws` | 新增：发起申请（AGENT/MEMBER，须实名通过） |
| `GET /api/withdraws` | 新增：列表（ADMIN 全量/其余仅自己，含 `pendingSum`） |
| `GET /api/withdraws/:id` | 新增：详情（本人或 ADMIN） |
| `POST /api/withdraws/:id/approve` | 新增：审核通过（事务扣款 + 写流水） |
| `POST /api/withdraws/:id/reject` | 新增：审核驳回（reason 必填） |
| `DELETE /api/withdraws/:id` | 新增：撤销待审申请 |
| `GET /api/dashboard/stats` | cards 新增 `pendingWithdrawCount`（仅 ADMIN 响应下发） |

### 代码结构

- `WithdrawRequest` 表：`wdNo 唯一 / amount 恒正 / method(ALIPAY·WECHAT·BANK) / status(PENDING·APPROVED·REJECTED) / transactionId 唯一关联通过时产生的 WITHDRAW 流水`；User、Transaction 各加反向关系。
- `doApprove` 复刻订单审核的事务模式：申请单/用户读取与校验全部在 `prisma.$transaction` 内（SQLite 写事务串行），复查 PENDING 与余额，冲突经 `conflict()` 转统一错误响应。
- 前端类型收口 `types.ts`（`Withdrawal/WithdrawStatus/WithdrawMethod/WithdrawListResult`），枚举映射收口 `format.ts`（`WITHDRAW_STATUS/WITHDRAW_METHOD`），接口封装 `api/withdraw.ts`。

### 改动文件

- 后端：`prisma/schema.prisma`、`src/routes/withdraws.js`（新增）、`src/routes/dashboard.js`、`src/index.js`
- 前端：`src/api/withdraw.ts`（新增）、`src/api/types.ts`、`src/utils/format.ts`、`src/views/withdraw/MyWithdraw.vue`（新增）、`src/views/withdraw/WithdrawReview.vue`（新增）、`src/views/withdraw/components/WithdrawReviewDialog.vue`（新增）、`src/router/index.ts`、`src/layouts/components/SideMenu.vue`、`src/views/dashboard/Dashboard.vue`、`frontend/dist/**`（重新构建）
- 文档：`docs/API契约-v2.1.md`（§10）、`docs/数码报单后台管理系统-PRD.md`（§十六）、本文件
- （新增）`scripts/qa-withdraw-review.cjs`：CDP 无头 Chrome 全链路冒烟脚本

## v2.6 用户管理实名快照查看（2026-09-18）

管理员需要核对已实名用户的实名信息（姓名/证件号/照片），此前只有「实名审核」入口（仅待审核状态可见），已通过用户没有查看入口。

## v2.5 品类计价双模式（2026-09-17）

### 变更背景

v2.4 的代理收购价只有「下浮比例」一种计价方式（`代理收购价 = 上游报价 × (1 − 下浮%)`）。
实际业务中部分品类（尤其高价机型）更适合按**固定金额**下浮，故新增第二种计价方式，两种方式可混用。

### 新增功能

1. **每行二选一计价方式**：品类下浮设置弹窗新增「计价方式」下拉，可选：
   - `下浮比例`：`代理收购价 = 上游报价 × (1 − 下浮%/100)`
   - `减固定金额`：`代理收购价 = 上游报价 − 固定金额（元）`
2. **全局一键切换**：弹窗顶部新增「全局计价方式」单选，点击即套用到下方全部品类；单行仍可再单独调整。
3. **单位与精度联动**：计价数值单位随方式在 `%` 与 `元` 之间自动切换；百分比限 0–100（1 位小数），金额限 0–1000000（2 位小数）。
4. **界面更名**：弹窗「下浮比例设置」→「品类计价设置」；工具栏按钮同步更名；导入结果摘要按方式渲染（如 `手机 −¥100` / `平板电脑 3%`）。

### 数据模型

- `Setting` 新增 key **`markdown_rules`**，值为 `{ 品类: { mode: 'percent'|'fixed', value } }`。
- 旧 key `markdown_rates` **保留不删**：读取时若 `markdown_rules` 不存在，自动把旧数据规范化为 percent 规则返回。
- **存量数据无需迁移**：现有 `markdown_rates`（手机 2 / 平板电脑 3 / 智能穿戴 4 / 笔记本电脑 3 / 配件 5）开箱即用，打开弹窗即显示为「下浮比例」模式。
- 写入只写新 key，避免同一品类出现两份规则产生优先级歧义。
- 无 Prisma schema 变更，**无需执行 `prisma db push`**。

### 接口变更

| 接口 | 变更 |
| --- | --- |
| `GET /api/settings/markdown` | 返回 `{ rules, rates }`；`rates` 为 percent 品类派生映射（兼容旧调用） |
| `PUT /api/settings/markdown` | 接收 `{ rules }`；**同时兼容旧的 `{ rates: {品类:数字} }`**（自动按 percent 规范化），部署窗口期旧页面提交不会 400 |
| `POST /api/products/import` | 响应新增 `markdownRules`；`markdownRates` 保留（仓库外 kdocs 采集管道不受影响） |
| `POST /api/products/recalc` | 同上；计价 ≤0 的产品**置空价格并下架**（此前会落库负价，已修正） |

校验规则：percent 限 0–100，fixed 限 0–1000000 且不可为负，越界返回 400。

### 代码结构

- 计价公式收敛到 `backend/src/util.js` 的 **`computeAgentPrice(upstream, rule)`** 单一函数，Excel 导入与「保存并重算」两条路径共用，避免两处公式漂移。
- 新增 `getMarkdownRules()`（含旧 key 规范化回落）与 `rulesToRates()`（派生兼容字段）。

### 改动文件

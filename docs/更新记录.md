## v2.6 用户管理实名快照查看（2026-09-18）

### 变更背景

管理员需要核对已实名用户的实名信息（姓名/证件号/照片），此前只有「实名审核」入口（仅待审核状态可见），已通过用户没有查看入口。

### 新增功能

1. **双击查看快照**：用户管理列表双击「已实名」徽章，弹出只读「实名信息快照」：左侧身份证照片（可点击放大），右侧实名状态/用户姓名/手机号/真实姓名/完整身份证号/提交时间/审核时间。
2. **纯只读**：快照弹窗无通过/驳回/重置实名等任何操作入口，仅「关闭」。
3. **权限与范围**：仅 ADMIN 可触发；「已实名」徽章显示手型光标提示可交互；待审核（走「实名审核」）、已驳回（悬浮驳回原因）、未实名徽章无双击行为，原有交互不变。

### 接口变更

无。复用现有管理端接口 `GET /api/realname/:userId`（完整证件号）与 `GET /api/realname/:userId/photo`（照片流）。

### 代码结构

- `RealnameReviewDialog.vue` 新增 `viewOnly` prop：标题切换为「实名信息快照 - 用户名」，隐藏重置实名等操作按钮，提示语改为「实名信息快照，仅供查看」；审核模式行为不变。
- `Users.vue` 实名列「已实名」徽章绑定 `@dblclick`，新增 `openSnapshot`（ADMIN 守卫）与第二个只读弹窗实例，与审核弹窗互不干扰。

### 改动文件

- `frontend/src/views/users/Users.vue`
- `frontend/src/views/users/components/RealnameReviewDialog.vue`
- （新增）`scripts/qa-dblclick-realname.cjs`：CDP 无头 Chrome 冒烟测试脚本（登录 → 双击徽章 → 校验弹窗 → 截图）

### 验收结果（全部实测）

- `frontend` `npm run build` 编译通过。
- 无头 Chrome 冒烟测试：双击「已实名」弹窗标题/照片/证件号/时间字段完整，弹窗内无任何操作按钮；双击「未实名」无弹窗。
- 后端零改动，无 Prisma schema 变更，**无需执行 `prisma db push`**。

### 部署注意

- 仅前端变更：服务器只需更新 `frontend/dist`，无需重启 Node 项目（Express 静态文件即时生效）。
- 自本版本起代码仅推送 GitHub，Gitee 冻结不再更新。

## v2.5 品类计价双模式（2026-09-17）

### 变更背景

v2.4 的代理收购价只有「下浮比例」一种计价方式（`代理收购价 = 上游报价 × (1 − 下浮%)`）。
实际业务中部分品类（尤其高价机型）更适合按**固定金额**下浮，故新增第二种计价方式，两种方式可混用。

### 新增功能

1. **每行二选一计价方式**：品类下浮设置弹窗新增「计价方式」下拉，可选：
   - `下浮比例`：`代理收购价 = 上游报价 × (1 − 下浮%/100)`
   - `减固定金额`：`代理收购价 = 上游报价 − 固定金额（元）`
2. **全局一键切换**：弹窗顶部新增「全局计价方式」单选，点击即套用到下方全部品类；单行仍可再单独调整。
3. **单位与精度联动**：计价数值单位随方式在 `%` 与 `元` 之间自动切换；百分比限 0–100（1 位小数），金额限 0–1000000（2 位小数）。
4. **界面更名**：弹窗「下浮比例设置」→「品类计价设置」；工具栏按钮同步更名；导入结果摘要按方式渲染（如 `手机 −¥100` / `平板电脑 3%`）。

### 数据模型

- `Setting` 新增 key **`markdown_rules`**，值为 `{ 品类: { mode: 'percent'|'fixed', value } }`。
- 旧 key `markdown_rates` **保留不删**：读取时若 `markdown_rules` 不存在，自动把旧数据规范化为 percent 规则返回。
- **存量数据无需迁移**：现有 `markdown_rates`（手机 2 / 平板电脑 3 / 智能穿戴 4 / 笔记本电脑 3 / 配件 5）开箱即用，打开弹窗即显示为「下浮比例」模式。
- 写入只写新 key，避免同一品类出现两份规则产生优先级歧义。
- 无 Prisma schema 变更，**无需执行 `prisma db push`**。

### 接口变更

| 接口 | 变更 |
| --- | --- |
| `GET /api/settings/markdown` | 返回 `{ rules, rates }`；`rates` 为 percent 品类派生映射（兼容旧调用） |
| `PUT /api/settings/markdown` | 接收 `{ rules }`；**同时兼容旧的 `{ rates: {品类:数字} }`**（自动按 percent 规范化），部署窗口期旧页面提交不会 400 |
| `POST /api/products/import` | 响应新增 `markdownRules`；`markdownRates` 保留（仓库外 kdocs 采集管道不受影响） |
| `POST /api/products/recalc` | 同上；计价 ≤0 的产品**置空价格并下架**（此前会落库负价，已修正） |

校验规则：percent 限 0–100，fixed 限 0–1000000 且不可为负，越界返回 400。

### 代码结构

- 计价公式收敛到 `backend/src/util.js` 的 **`computeAgentPrice(upstream, rule)`** 单一函数，Excel 导入与「保存并重算」两条路径共用，避免两处公式漂移。
- 新增 `getMarkdownRules()`（含旧 key 规范化回落）与 `rulesToRates()`（派生兼容字段）。

### 改动文件

### 部署注意

1. **`.env` 不入库**（含真实 `JWT_SECRET` / `IMPORT_KEY`），服务器上已有独立 `.env`，更新代码时**切勿覆盖**。参考模板见 `backend/.env.example`。
2. 本次**无需数据库迁移**，直接更新代码 + 重启 Node 项目即可。
3. 前端源文件变更后需 `cd frontend && npm run build` 重新构建 `frontend/dist`（服务器直接托管该产物）。
4. 此更新对**历史订单无影响**：订单建单时已快照 `upstreamPrice` 与 `profit`，不会因计价规则调整而变动。

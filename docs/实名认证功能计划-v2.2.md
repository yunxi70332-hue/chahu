# 实名认证功能计划 v2.2

> 需求:账号开通后进行实名登记,**不接第三方验证**——用户上传身份证人像面照片,管理员审核;**审核通过后锁定,不允许再次更改**。
> 状态:计划文档,待确认后开工。

---

## 一、产品设计

### 1.1 流程

```
用户(代理/会员)登录 ──► 未实名:顶部提醒 + 「实名认证」菜单
        │
        ▼
填写真实姓名 + 身份证号 + 上传身份证人像面照片 ──► 状态:待审核
        │
   管理员(用户管理页)审核:核对照片与姓名/证号
        │
   ┌────┴─────┐
 通过(绿)   驳回(红,必填原因)
   │              │
 锁定 ✓       可重新上传
 不允许再改
```

### 1.2 规则(默认值,可改)

| # | 规则 | 默认 |
| --- | --- | --- |
| 1 | 适用角色 | **AGENT + MEMBER**(收货打款涉资金,实名是底线);ADMIN 不需要 |
| 2 | 未实名的影响 | **拦截报单提交**(前端隐藏禁用 + 后端 400 兜底);可登录、可查看,不可交易。管理员代客下单同样要求报单人已实名 |
| 3 | 登记字段 | 真实姓名 + 身份证号(18 位格式校验)+ 身份证人像面照片(jpg/png/webp ≤5MB) |
| 4 | 锁定 | APPROVED 后:前端不再显示修改入口,后端拒绝重复提交(400「实名已通过,不可修改」);ADMIN 保留「重置实名」用于纠错 |
| 5 | 待审核 | 不可重复提交,防刷 |
| 6 | 照片安全 | 存本地 `D:\baodan-data\uploads\idcards\`,**不落数据库、不经第三方**;查看走鉴权接口,**仅本人和 ADMIN 可看**,前端 blob 加载(照片 URL 不裸奔) |
| 7 | 历史版本 | V1 只留当前一次(不存历次上传记录),P2 再考虑 |

### 1.3 用户视角

- **用户(代理/会员)**:登录后若未实名 → 顶部通知条引导 → 「实名认证」页填写并上传 → 显示"待审核";若被驳回 → 显示原因 → 修改重传;通过后 → 绿色"已实名"卡片,无修改入口。
- **管理员**:用户管理页新增「实名状态」列(未实名/待审核/已实名/已驳回四色 tag)+ 状态筛选;点「审核」弹出大图预览 + 姓名/证号 → 通过 / 驳回(必填原因);「重置实名」纠错入口。
- **建单**:向导里报单人下拉只列已实名用户(后端兜底校验);未实名用户自己报单时提交按钮禁用并引导去实名。

## 二、技术方案

### 2.1 数据模型(User 表新增字段,SQLite)

```
realName            String?   // 真实姓名
idCardNo            String?   // 身份证号
idCardPhoto         String?   // 照片文件名(存 D:\baodan-data\uploads\idcards\)
realnameStatus      String @default("NONE")  // NONE / PENDING / APPROVED / REJECTED
realnameRejectReason String?
realnameReviewedBy  Int?
realnameReviewedAt  DateTime?
realnameSubmittedAt DateTime?
```

### 2.2 API 契约新增(§9)

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | /realname/submit | AGENT/MEMBER | multipart:realName/idCardNo/photo → 状态 PENDING;APPROVED 后 400 |
| GET | /realname/me | 登录 | 自己的实名状态与信息(不含照片地址) |
| GET | /realname/:userId/photo | 本人或 ADMIN | 鉴权流式返回照片,他人访问 403 |
| POST | /realname/:userId/approve | ADMIN | → APPROVED,锁定 |
| POST | /realname/:userId/reject | ADMIN | {reason 必填} → REJECTED |
| POST | /realname/:userId/reset | ADMIN | 清空回 NONE(纠错用) |

连带修改:`GET /users` 列表项与 `GET /users/options` 增加实名状态字段(options 默认只返回已实名,传 `all=1` 返回全部);`POST /orders` 校验报单人 realnameStatus=APPROVED,否则 400「请先完成实名认证」。

### 2.3 前端

1. 新页面 `/realname`(AGENT/MEMBER 菜单新增「实名认证」):状态卡 + 表单(姓名/证号/拖拽上传带预览)/驳回原因提示
2. 用户管理:实名状态列 + 筛选 + 「实名审核」弹窗(照片大图 + 信息核对 + 通过/驳回)+ 重置实名
3. 建单向导:报单人下拉过滤已实名;未实名用户本人建单时禁用提交并引导
4. 未实名登录后 ElNotification 引导
5. 主题/组件复用现有设计系统(#0052D9、四色状态:未实灰/待审橙/已实绿/驳回红)

## 三、验收标准

- [ ] 未实名/待审核用户提交报单被拦(前端禁用 + 后端 400),管理员代客下单同样被拦
- [ ] 上传后状态待审核;管理员通过后:用户端无修改入口,重复提交接口 400
- [ ] 驳回必填原因,用户可见原因并可重新上传
- [ ] 照片仅本人与 ADMIN 可访问(他人 403,未登录 401);照片文件落 D 盘、不经任何第三方
- [ ] 身份证号 18 位格式校验;照片类型/大小限制生效
- [ ] 用户管理可按实名状态筛选,审核操作留审核人与时间
- [ ] `pnpm build` 通过;回归脚本 23/23 不回归 + 新增实名回归用例

## 代码更新流程（v2.5 实测，后续更新照此执行）

> ⚠️ **香港服务器无法访问 gitee.com**（已实测：`curl https://gitee.com/` 无响应，`git clone` 超时；但 npm/百度等正常）。
> 因此**不能**在服务器上 `git pull`，代码更新走「本机打包 → 上传 → 覆盖」通道。

```bash
# 1) 本机:提交并推送到 Gitee(仅作版本留档)
cd /e/数码报单 && git add -A && git commit -m "..." && git push

# 2) 本机:打包待更新文件(改前端须先 cd frontend && npm run build)
#    包内不要含 backend/.env,否则会覆盖服务器密钥

# 3) 上传到服务器(走宝塔 MCP 的 Upload 工具,或面板文件管理)
#    上传后解压到 /tmp/deploy-extract

# 4) 服务器:更新前先备份可回滚
STAMP=$(date +%Y%m%d-%H%M%S)
mkdir -p /www/baodan-data/backups/code-$STAMP
cp -a /www/baodan/backend/src  /www/baodan-data/backups/code-$STAMP/backend-src
cp -a /www/baodan/frontend/dist /www/baodan-data/backups/code-$STAMP/frontend-dist

# 5) 覆盖源码与 dist(.env 不在包内,不受影响;如需保险先 md5sum 记录)
D=/tmp/deploy-extract; T=/www/baodan
cp -f $D/backend/src/*.js            $T/backend/src/
cp -f $D/backend/src/routes/*.js     $T/backend/src/routes/
cp -f $D/backend/prisma/seed.js      $T/backend/prisma/
rm -rf $T/frontend/dist && cp -a $D/frontend/dist $T/frontend/dist
chown -R www:www $T

# 6) 语法检查后重启面板 Node 项目
cd $T/backend && for f in src/util.js src/routes/*.js src/index.js; do node --check $f; done
# 宝塔面板 → Node 项目 baodan → 重启(或 MCP NodeProjectControl action=restart)

# 7) 验证
curl -s http://127.0.0.1:3002/api/health                      # {"ok":true}
curl -s http://127.0.0.1:3002/ | grep -o 'assets/index-[^"]*'  # 入口 bundle 名应为新构建产物
tail -15 /www/wwwlogs/nodejs/baodan.log
```

**无需数据库迁移**：v2.5 只新增 `Setting` 行，不使用 `prisma db push`。

## 三、路线 A Runbook（本机服务化，照抄执行）

### A1 服务化（NSSM，开机自启 + 崩溃拉起）

```powershell
# 1) 下载 nssm 到 C:\Tools\nssm\（https://nssm.cc/download）
# 2) 管理员 PowerShell：
C:\Tools\nssm\nssm.exe install baodan "C:\Program Files\nodejs\node.exe" "E:\数码报单\backend\src\index.js"
C:\Tools\nssm\nssm.exe set baodan AppDirectory "E:\数码报单\backend"
C:\Tools\nssm\nssm.exe set baodan AppStdout "D:\baodan-data\logs\baodan.out.log"
C:\Tools\nssm\nssm.exe set baodan AppStderr "D:\baodan-data\logs\baodan.err.log"
C:\Tools\nssm\nssm.exe start baodan
```

先停掉当前手工 node 进程再 start，避免端口冲突。

### A2 每日备份计划任务（脚本已实测通过）

```powershell
schtasks /Create /TN "baodan-backup" /SC DAILY /ST 23:30 /TR "powershell -ExecutionPolicy Bypass -File E:\数码报单\scripts\backup.ps1"
```

次日检查 `D:\baodan-data\backups\` 出现新目录即成功。

### A3 上线日数据初始化（顺序不可换）

1. `cd E:\数码报单\backend && npm run seed` —— 重置为干净库
2. 管理员建正式代理/会员账号，**全部改强密码**（admin123/agent123/member123 必须消失）
3. 双击 `D:\学习良心\kdocs-export\一键导出.bat` → 金山文档点「⬇ 导出」走通道 A 导入当日正式报价；备用：产品管理页手动导入 xlsx
4. 人工核对导入汇总中的「异常自动下架」条数是否与报价表预期一致

- 本机防火墙放行 3001 入站（管理员：`netsh advfirewall firewall add rule name="baodan" dir=in action=allow protocol=TCP localport=3001`）

## 四、路线 B Runbook（外网宝塔服务器）

**前提（缺一不可，需老板提供）**：① 服务器 IP + 宝塔面板账号；② 是否有域名及要不要 HTTPS。

1. **服务器环境**：宝塔 → 安装 Node ≥ 20 + PM2；建站点目录如 `/www/baodan`
2. **代码推送**：上传 `backend/`（不含 node_modules）+ 已构建的 `frontend/dist`（Express 托管 dist，一站式单进程）；服务器上 `npm install && npx prisma db push`
3. **数据与配置迁移**：
   - 首次上线直接服务器新 seed（推荐）；若要带走本机数据，拷贝 `D:\baodan-data\baodan.db` + `uploads\`
   - `.env` 三个关键值：`DATABASE_URL` 改服务器路径；`JWT_SECRET` **换新的**（旧令牌全部失效属预期）；`IMPORT_KEY` 若与 kdocs 通道保持对接则**原样保留**，并把 `D:\学习良心\kdocs-export\baodan.json` 里的推送地址从 `localhost:3001` 改为服务器公网地址
4. **反代与安全（外网暴露前必做，对应技术债清单）**：
   - 宝塔 Nginx 反代 3001，绑定域名 + 申请 Let's Encrypt 证书
   - `app.use(cors())` 收紧为站点域名；登录接口加失败 5 次锁 10 分钟
   - 服务器侧每日备份：cron 调 sqlite3 `.backup` + 打包 `uploads/idcards`（实名照片绝不能丢）
5. **验收**：外网手机热点访问域名 → 登录 → 报单 → 审核到账 → kdocs 推送报价成功

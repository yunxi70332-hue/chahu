## 二、多智能体编排

**总原则:契约先行、文件所有权隔离、自测后交付、主线程集成验收。**

### 阶段 0 — 主线程:接口契约(开工第一步)

写 `docs/API契约-v2.1.md`,内容:全部端点请求/响应 JSON 示例、枚举(ADMIN/AGENT/MEMBER、PENDING/APPROVED/REJECTED、RECHARGE 补款/WITHDRAW 提现/ORDER 报单打款/COMMISSION 佣金/ADJUST 调整)、佣金自动算规则、错误码、第二节设计 token。**这是所有 Agent 的唯一事实来源**,前端 Agent 无需后端运行即可开发。

### 阶段 1 — 双 Agent 并行

#### Agent-A「后端 v2.1」(独占 `backend/`)

1. schema:`Setting` 模型(key 唯一/value,存品类佣金比例 JSON)、`Order.logisticsNo String?`、`Order.product` 显式 `onDelete: SetNull` → `db push`
2. 订单审核 APPROVE 反转:余额 += 本金(流水 ORDER,备注 `报单打款 单号`)+ 佣金(流水 COMMISSION,备注 `单号 · 品类 比例%`),删除余额不足拦截
3. 建单:佣金未显式传 = 总额 × 品类比例 / 100(2 位舍入);显式传用手动值;支持 logisticsNo
4. 新增 `routes/settings.js`:GET /api/settings/commission(登录即可)、PUT(仅 ADMIN)
5. `POST /api/products/import`(仅 ADMIN,multer + exceljs):按表头映射 → 整批替换产品库;价格 ≤0/空 → DISABLED;返回 `{ imported, disabled, quoteDate }`
6. transactions 接口返回体增加 `{ incomeSum, expenseSum }`(按当前筛选范围)
7. dashboard 口径:今日报单数/报单金额/**今日打款(ORDER+COMMISSION 合计)**/今日提现/待审核/用户数;AGENT、MEMBER 按范围过滤
8. seed 重跑:余额从 0 靠审单累积,提现流水保留,写入初始品类佣金比例
9. **自测**:curl 走通 登录→建单→审核→查余额与流水→导入 样例 xlsx→看板

#### Agent-B「前端基建 + 登录」(独占 `frontend/`)

1. Vite + Vue3 + TS + Element Plus + Pinia + Vue Router + ECharts + Axios
2. 主题定制:主色 #0052D9,success/warning/danger 覆盖为 #2BA471/#E37318/#D54941;全局字体、卡片、表格样式
3. axios 封装:token 注入、401 跳登录、错误 ElMessage
4. 响应式布局:桌面暗色侧栏(#191919),≤768px 抽屉;菜单按角色:ADMIN 全量 / AGENT 看板·报单·流水 / MEMBER 报单·流水;顶栏用户菜单(修改密码/退出)
5. 登录页:左侧品牌区(「单」logo、数码报单系统·内部版、郑州天讯商贸行、宣传语),右侧手机号+密码+记住登录(12h)
6. **预注册全部路由**(懒加载占位视图,后续页面 Agent 只替换自己的 view 文件);全局组件:`StatusTag` 三色、金额格式化(¥千分位)、手机号打码、页面容器

# 价格采集 × 代理报单 中介模式联动(v2.4)

## 模型转变(一句话)

现在:平台按大富报价**全款打款给报单人,还额外发佣金**(贴钱)。
改后:**中介模式**——大富报价为上游价,代理看到的是「报价 ×(1-品类下浮%)」的收购价;审核通过按收购价打款,差价 = 系统利润,每单快照、看板可视。

**已定决策**:①代理只看下浮后价,大富原价仅总部可见;②按品类百分比下浮;③取消佣金机制,利润=差价;④**报价更新双通道并存**(脚本自动 + 人工上传,见第四节)。

## 一、数据模型(backend/prisma/schema.prisma)

- `Product` 加 `upstreamPrice Float?`(大富原价);`price` 语义变为「代理收购价」
- `Order` 加 `upstreamPrice Float?`(下单时上游价快照)+ `profit Float @default(0)`(=(上游价-结算价)×数量,建单时算好)
- `Setting` 新 key `markdown_rates`(`{品类: 下浮%}`),替代 `commission_rates`(旧 key 及历史 COMMISSION 流水仅保留只读兼容,新单不再产生佣金)
- 迁移:`prisma db push` 后跑一次性脚本——存量产品 `upstreamPrice = price`(它们当初就是按大富价导入的);历史订单 profit 保持 0

## 二、后端改造(6 处)

1. **导入逻辑(双通道共用核心)** [routes/products.js](E:\数码报单\backend\src\routes\products.js)
   - `/import`:「参考回收价」列读为 upstreamPrice,price = round2(upstream ×(1-该品类下浮%));上游价 ≤0/空 → DISABLED(现有规则不变);下浮后 ≤0 也 DISABLED
   - 返回统计增加:导入数 / 下架数 / 报价日 / **应用的下浮比例摘要**(让操作者知道这批价格按什么规则下的浮)
   - 新增 `POST /products/recalc`(ADMIN):改下浮比例后一键重算全部在售代理价;`upstreamPrice` 为空的行先兜底 `= price` 再算
   - 列表/选品接口按角色裁剪:非 ADMIN 不下发 `upstreamPrice`(商业机密)
2. **下浮设置** [routes/settings.js](E:\数码报单\backend\src\routes\settings.js):`GET/PUT /settings/markdown`(0-100 校验,结构复用佣金设置)
3. **打款简化** [routes/orders.js](E:\数码报单\backend\src\routes\orders.js)
   - `doApprove`:删掉佣金分支,通过 = 余额 += 货款,一笔 ORDER 流水
   - 建单:忽略 commission 入参(恒 0);快照 upstreamPrice 并算 profit;**利润为负(议价高于上游价)不硬拦,审核列表标红**,由总部人工把关
4. **双通道鉴权**: `/import` 同时接受 ①管理员 JWT(现有,人工通道)②`X-Import-Key` 请求头(`.env` 配强随机 `IMPORT_KEY`,脚本通道,仅本地管道用)
5. **看板** [routes/dashboard.js](E:\数码报单\backend\src\routes\dashboard.js):总部新增「今日差价利润」= 今日已审单 Σprofit
6. **seed**:演示数据改为下浮模式(默认 手机 2%、平板 3%、穿戴 4%、笔记本 3%、配件 5%,可后台改)

## 三、前端改造(6 处)

1. **OrderWizard**:删「品类佣金率/佣金金额」两个字段,合计 = 货款,提示改为「审核通过后按此价打款」
2. **Orders**:佣金列改为「差价」列(**仅总部可见**,代理/会员看不到);编辑弹窗删佣金字段;详情页同样按角色显示
3. **Products**(总部页):双价列「上游价/代理收购价」+ 下浮设置弹窗(原 CommissionDialog 改造),保存后引导「一键重算在售价格」
4. **Dashboard**:第 7 张指标卡「今日差价利润」(仅总部)
5. **Transactions**:类型筛选保留 COMMISSION(历史数据),无新增
6. 向导/选品默认价 = 代理收购价(即 product.price,机制不变,只是语义)

## 四、报价更新双通道(核心需求)

**同一套导入核心,两个入口并存,按场景选用:**

### 方案 A · 脚本式自动更新(无人值守,日常首选)
```
kdocs 网页点「导出」→ receiver 收 SVG → 自动清洗 xlsx → 自动 POST 导入(X-Import-Key)→ 产品库换价(自动下浮)→ 代理立即按新价报单
```
- [receiver.py](D:\学习良心\kdocs-export\scripts\receiver.py) 在 `--auto-clean` 清洗完成后,读取 `kdocs-export/baodan.json`(配置 `{"url":"http://127.0.0.1:3001","key":"<IMPORT_KEY>"}`,文件不存在则静默跳过,不影响原工具独立使用)
- 把 `结果/*.xlsx` 以 `X-Import-Key` 头 POST 到 `/api/products/import`,日志打印导入统计
- 适合:每天例行更新报价,操作者只需「双击 bat + 网页点一下」

### 方案 B · 人工导入(手动兜底,随时可用)
- 管理员在「产品管理 → 导入」上传 xlsx(现有页面上传流程保留,鉴权走管理员登录态)
- 导入弹窗文案更新:说明「将按当前下浮比例自动计算代理收购价,异常价自动下架」,导入结果面板展示下浮比例摘要
- 适合:bat/脚本通道故障时兜底、临时用历史报价表回滚、上线初期人工核对流程
- 17 列清洗产物与导入表头本来就兼容,双通道喂的是同一个文件格式

### 通道一致性保障
- 两个入口最终调同一个 `/import` 处理器,价格规则、下架规则、统计口径完全一致,不存在"脚本导的和手动导的价不一样"
- 顺手项:清洗规则 QUOTE_DATE 硬编码改为默认当天(表格内有日期则以表内为准),避免脚本通道天天导旧日期

## 边界与风险

- 价格精度:下浮价 round2;极低价(配件几元钱)下浮后可能 ≤0 → 自动下架,和现有异常价规则一致
- 议价单(代理改价高于上游)不拦截只标红——审核页利润红色展示,总部人工判断
- 历史佣金流水/佣金列只读保留,不做破坏性删除,对账不乱
- 存量 1685 产品迁移后代理价会**整体下浮**,若演示期代理按旧价建过待审单,审核前应重新核对(建议上线日清空演示单)

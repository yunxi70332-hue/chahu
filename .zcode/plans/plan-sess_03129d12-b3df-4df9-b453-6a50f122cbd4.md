# 品类计价规则：新增「固定上游报价减 XXX 金额」模式

## 目标

在现有的「品类下浮比例设置」弹窗里，让每个品类可以二选一：
- **下浮比例**：`代理收购价 = 上游报价 × (1 − 下浮%/100)`（现有行为）
- **固定减额**：`代理收购价 = 上游报价 − 固定金额`

同时提供一个**全局计价方式选择器**，一键把全部品类切成同一种方式，每行仍可单独覆盖。

## 数据模型

新增 Setting key `markdown_rules`，值为 `{ 品类: { mode: 'percent' | 'fixed', value: number } }`。

**保留** 旧 key `markdown_rates`（`{品类: 下浮%}`）不动、不删：读取时若 `markdown_rules` 不存在则把旧数据规范化为 `{mode:'percent', value}` 返回，因此现有 DB 数据无需迁移即可继续工作，写入时只写新 key。这样避免了「两张表 + 隐含优先级」的坑（同一品类不可能同时存在两条规则）。

## 计算规则（唯一真源）

在 `backend/src/util.js` 增加：

```js
export function computeAgentPrice(upstream, rule) {
  if (!Number.isFinite(upstream)) return null
  const value = Number(rule?.value) || 0
  const price = rule?.mode === 'fixed' ? upstream - value : upstream * (1 - value / 100)
  return round2(price)
}
```

`≤ 0` 一律沿用现有策略：导入/重算时自动 DISABLED（防免费/负价收购），不做特殊例外。

## 后端改动

1. **`backend/src/util.js`** — 新增 `getMarkdownRules()`（读 `markdown_rules`，缺失/异常时回落旧 `markdown_rates` 并规范化）、`computeAgentPrice()`。保留 `getMarkdownRates()` 供兼容读取。
2. **`backend/src/routes/settings.js`** — `GET /markdown` 返回 `{ rules }`（并附 `rates` 派生字段供旧前端兼容）；`PUT /markdown` 接收 `{ rules }`，逐项校验 `mode ∈ {percent,fixed}`、`value` 为 0–100（percent）或 0–1e6（fixed）的有限数，全量覆盖写入 `markdown_rules`；**同时兼容旧的 `{ rates: {品类: 数字} }` 请求体**，自动规范化为 percent 规则（防止部署窗口期旧页面提交报 400）。
3. **`backend/src/routes/products.js`** — `POST /import`（现 287 行）与 `POST /recalc`（现 341 行）改用 `computeAgentPrice(upstream, rules[category])`；两处响应新增 `markdownRules`，并保留 `markdownRates`（仅 percent 品类的派生映射）以兼容仓库外的 kdocs 采集管道。
4. **`backend/prisma/seed.js`** — 默认数据改写成 `markdown_rules` 的规则对象，价格计算与上面同式（11 个品类默认值不变，仍是 percent）。
5. 无需 `prisma db push`：`Setting` 是 key/value 表，无 schema 变更。

7. **`frontend/src/api/settings.ts` / `products.ts`** — 类型签名跟随更新（`setMarkdown(rules)`、`recalcPrices()` 返回体）。
8. **`MarkdownDialog.vue`（主体改动）**
   - 行模型改为 `{ name, mode: 'percent' | 'fixed', value, preset }`。
   - 弹窗顶部新增**全局计价方式**单选（下浮比例 / 减固定金额）：切换即把全部行设为该方式，并作为新增行的默认方式；每行仍可用下拉单独改。

   - 校验：名称非空、不重复（沿用现有提示）；fixed 模式金额必须 ≥ 0 的有限数。

## 验证

- **后端 API**：启动 `node src/index.js`，用 curl 以管理员登录拿 token → `GET /api/settings/markdown` 确认旧数据被规范化为 percent 规则 → `PUT` 写入混合规则（部分 fixed）→ `POST /api/products/recalc` 核对返回 `updated/disabled` → 抽样查产品：percent 品类价格 = `上游×(1−%)`、fixed 品类 = `上游−金额`、异常价已 DISABLED。
- **导入通道**：用 `backend/node_modules/exceljs` 生成一个含 3 个品类的 .xlsx 小样本，走 `POST /api/products/import`（JWT 与 `X-Import-Key` 两条通道各测一次），确认两条通道价格口径一致、响应含 `markdownRules`。测试后重新导入真实报价表或恢复原数据。
- **前端**：`npm run build`（frontend）重建 `frontend/dist`（Express 托管的就是这个目录），重启后端进程；用 `qa-screenshots/capture-v24.js` 的 playwright 模式写一个 `capture-v25.js`，截图验证弹窗（全局切换 + 每行二选一 + 单位切换 + 保存后产品列表双价正确），并检查页面无 JS 报错。

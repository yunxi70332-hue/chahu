# 数码报单系统 — 按拍板决策落地方案

## 已确认的决策(写入 PRD v2.1)
1. **资金方向反转**:回收模式,审核通过 = 平台打款给报单人:**余额增加 本金(货款)+佣金**,写两笔流水(报单打款/佣金);不做余额不足拦截;提现为管理员线下转账后后台记账扣余额(不做提现审批)
2. **佣金**:品类比例统一设置(管理员可批量配比例)+ 报单时可单笔手动改
3. **报价表**:V1 就做 Excel 一键导入(整批替换产品库,历史单靠快照字段不受影响)
4. **会员端**:会员可登录同一套系统,自助报单+查自己的单和流水(角色化菜单,不做独立前台)
5. **异常报价**:价格≤0/为空的产品导入即下架,报单选品默认搜不到

## 后端改造(E:\数码报单\backend)
- `orders.js` 审核 APPROVE 逻辑反转:balance += totalAmount(流水 ORDER,+)、+= commission(流水 COMMISSION,+),删除余额不足校验
- 新增 `Setting` 模型(key/value 存品类佣金比例 JSON):GET/PUT `/api/settings/commission`(改仅 ADMIN);报单创建时佣金=总额×品类比例自动算,显式传入则用手动值
- 新增 `POST /api/products/import`(ADMIN,multer+exceljs 解析 xlsx):按表头映射 17 列 → 全量替换产品库;价格≤0/空置为 DISABLED;返回导入汇总
- `dashboard.js` 口径改为回收语义:今日报单数/今日报单金额/今日打款(ORDER+COMMISSION 合计)/今日提现/待审核/用户数;AGENT/MEMBER 按自己范围过滤
- seed 重跑:会员余额从 0 开始靠审单打款累积,保留提现流水;看板数字吻合
- 新增依赖:exceljs、multer;Order.product 关系显式 onDelete: SetNull

## 前端新建(E:\数码报单\frontend,Vite+Vue3+TS+Element Plus+Pinia+Router+ECharts+Axios)
- axios 封装(token 拦截/错误提示)、Pinia 登录态、路由守卫+角色菜单:ADMIN 全菜单;AGENT 看板/报单/流水;MEMBER 报单/流水
- 响应式布局:桌面固定侧栏、≤768px 抽屉;顶栏用户菜单(改密/退出)
- 登录页;看板(指标卡+7天趋势折线+状态饼图+品类柱图+待审直达)
